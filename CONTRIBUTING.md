# Contributing
Read [AGENTS.md](AGENTS.md), [development](docs/development.md) and [testing](docs/testing.md).

Use a small branch and PR per coherent change. Explain the observable behavior, hardware source,
independent tests, actual validation results and remaining limits. Include a plan for a new
instruction family, device or format, and an ADR when changing a cross-project contract.

Do not include firmware, games or external test corpora without a documented redistribution
basis. Self-authored tiny fixtures are encouraged. Report bugs with model/profile, build/commit,
reproduction steps, expected behavior and the first divergent trace where available.
Private user files should be identified by format and hash rather than attached by default.
